# خطة بناء لوحات التحكم ونظام الحجز الموثّق

## النتيجة المستهدفة
تحويل الأساس الحالي إلى مساحة عمل كاملة للمسافر والوكالة والمدير، مع حجز يبدأ كطلب وينتهي بموافقة الوكالة، وإشعارات تلقائية، وقسيمة موثّقة قابلة للطباعة والتحقق عبر QR.

## 1. أساس آمن للحجز والإدارة
- توسيع الحجز بحالة دفع واضحة، وطريقة الدفع، ورمز تحقق عشوائي آمن لا يكشف معرّف الحجز.
- اعتماد حالات الحجز: قيد المراجعة، مؤكّد، مرفوض، ملغى، مكتمل؛ ومنع القسيمة الموثّقة قبل موافقة الوكالة.
- تحديث قواعد الوصول بحيث يرى المسافر حجوزاته فقط، وتدير الوكالة حجوزاتها ورحلاتها فقط، ويملك المدير الصلاحيات الشاملة بعد التحقق من دوره.
- إضافة وجهات قابلة للإدارة في قاعدة البيانات، مع الاحتفاظ ببيانات الاكتشاف الحالية كمرجع احتياطي حتى لا تنكسر الصفحات القديمة.
- إضافة سجل إداري لتغييرات حالة الوكالات والحجوزات المهمة.

## 2. هيكل موحّد للوحات التحكم
- إنشاء تخطيط RTL موحّد بعمود جانبي للحاسوب وقائمة مدمجة للهاتف، مع عنوان الصفحة وحالة الحساب واختصارات واضحة.
- إبقاء الروابط الحالية كما هي، وإضافة الصفحات الفرعية الناقصة بدل حشر كل الأدوات في شاشة واحدة.
- إخفاء الأدوات غير المسموح بها حسب الدور، مع استمرار الحماية الفعلية في قاعدة البيانات وليس في الواجهة فقط.

## 3. لوحة المسافر `/dashboard/customer`
- القائمة: الرئيسية، الملف الشخصي، اكتشف، المفضلة، حجوزاتي، رحلاتي، الرسائل، الإشعارات، الإعدادات.
- عرض الرحلات القادمة، آخر طلبات الحجز وحالاتها، الوجهات المفضلة، ورحلات منشورة مقترحة بحسب الولاية والميزانية واهتمامات السفر.
- إضافة محرر تفضيلات السفر وحفظه فعليًا في الحساب، مع حالات تحميل وفراغ وأخطاء واضحة.
- فتح القسيمة فقط للحجز المؤكّد، والوصول للمحادثة والإشعار المرتبطين بالحجز.

## 4. لوحة الوكالة `/dashboard/agency`
- القائمة: الرئيسية، ملف الوكالة، رحلاتي، إضافة رحلة، الحجوزات، العملاء، الرسائل، الإحصاءات، الإعدادات.
- بطاقة ملف الوكالة تشمل الاسم والشعار والولاية والعنوان وحالة التوثيق، مع شارة التوثيق للوكالات المعتمدة فقط.
- تطوير نموذج الرحلة ليشمل: العنوان، الولاية، الوصف، صور الغلاف والمعرض، التواريخ، السعر بالدينار، المقاعد، الخدمات المشمولة وغير المشمولة، نقطة اللقاء، سياسة الإلغاء، والحفظ كمسودة أو الإرسال/النشر وفق حالة الوكالة.
- صفحات تشغيلية للحجوزات والعملاء والرسائل، مع قبول أو رفض الطلب وتحديث العدد المتاح للمقاعد بطريقة آمنة.
- إحصاءات حقيقية من بيانات الوكالة، دون أرقام تجريبية.

## 5. مسار الحجز والقسيمة الموثّقة
- إضافة طلب حجز مباشر من الرحلة المنشورة؛ يُنشأ بالحالة «قيد المراجعة» بدل التأكيد الفوري.
- عند القبول أو الرفض، تُحدّث الحالة ويصل إشعار للمسافر؛ ويُمنع تجاوز سعة الرحلة.
- إنشاء صفحة قسيمة `RIHLA Verified Booking Voucher` تضم مرجع الحجز، بيانات المسافر والوكالة والرحلة، التواريخ، العدد، المبلغ، حالة الدفع، وQR يحمل رابط تحقق موقّعًا.
- صفحة التحقق العامة تعرض أقل قدر لازم من البيانات وتتحقق من الرمز الآمن وحالة الحجز.
- زر طباعة/حفظ PDF باستخدام تنسيق طباعة مخصص يخفي التنقل ويخرج القسيمة وحدها بشكل احترافي.

## 6. لوحة المدير `/dashboard/admin`
- مؤشرات: إجمالي المسافرين، الوكالات، الوكالات الموثّقة، الرحلات النشطة، والحجوزات.
- وحدة مراجعة الوكالات: بيانات الوكالة ووثائقها وملاحظات المراجعة، ثم اعتماد أو رفض أو تعليق مع شارة موثقة عند الاعتماد.
- إدارة كاملة للوجهات والرحلات والمستخدمين: بحث وتصفية، إضافة/تعديل/حذف حيث ينطبق، وتغيير الأدوار عبر آلية محمية لا تسمح للمستخدم بمنح نفسه صلاحية.
- تأكيدات قبل العمليات الحساسة ورسائل نجاح/فشل مفهومة.

## 7. التحقق والجودة
- اختبار دورة كاملة بحساب مسافر ووكالة ومدير: نشر رحلة، طلب حجز، قبول، إشعار، فتح القسيمة، مسح رابط QR، ثم الطباعة.
- اختبار منع الوصول المتبادل بين الأدوار، ومنع إصدار قسيمة للحجز المرفوض أو المعلّق.
- التحقق بصريًا على الهاتف والحاسوب، مع حالات البيانات الفارغة والمحمّلة، والتأكد من عدم وجود أخطاء في الصفحة أو الشبكة.

## تفاصيل تقنية
- سنستخدم Lovable Cloud مع قواعد وصول على مستوى الصفوف، ووظائف خادمية موثّقة للعمليات الحساسة والعدادات الإدارية.
- سيُولَّد رمز التحقق عشوائيًا في قاعدة البيانات ويُخزَّن بصورة غير قابلة للتخمين؛ لن يحتوي QR على بيانات شخصية.
- صور الرحلات ووثائق الوكالات ستُرفع إلى مساحات تخزين منفصلة بصلاحيات المالك والمدير.
- لن نضيف بوابة دفع إلكترونية لأن الطلب يحدد «حالة الدفع» فقط؛ ستُدار الحالة إداريًا ضمن الحجز، مع بقاء طرق الدفع الحالية.
